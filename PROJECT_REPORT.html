📌 1. Problem Statement

Modern enterprise data centers manage hundreds of servers, firewalls, software licenses, and hardware assets across multiple locations. The core challenges are:

  • No unified visibility — asset status scattered across spreadsheets and siloed tools
  • Delayed threat detection — security breaches go undetected for days or weeks
  • Manual risk assessment — patch status, license expiry, and access risks evaluated manually
  • No audit trail — no automatic record of who accessed what, when
  • Attack surface unknown — no way to visualize how an attacker can move laterally between assets

💡 2. Our Solution

CyberShield Nexus is a full-stack security operations prototype built around NEDI — National Education Digital Infrastructure, a fictional scenario that simulates a centralized SOC environment for education-sector digital services. NEDI is entirely fictional and exists only to make the demonstration realistic, focused, and easy to evaluate. The project does not represent any real organization or government initiative.

⚙️ 4. Key Features

4.1 Authentication & RBAC

  • JWT (HMAC-SHA384) issued on login, validated on every request
  • BCrypt strength-12 password hashing
  • 3 roles: ADMIN (full), SERVER_ADMIN (manage servers), VIEWER (read-only)
  • Account lockout after 5 consecutive failures (15-minute ban)
  • Every login attempt (success or fail) written to AuditLog

4.2 Risk Engine (RiskEngineService)

Calculates a 0–100 risk score for every server using 5 independent factors:

Unpatched Server+30last_patch_date older than 90 days

4.3 BFS Attack Path (AttackPathService)

Uses Breadth-First Search on the asset graph to find the shortest path an attacker can travel from a compromised entry point to a high-value target.

Demo Attack Path (15 seeded edges):

USER:3 (viewer) → FIREWALL:1 → SERVER:1 (Web) → SERVER:2 (App) → SERVER:3 (DB)

Result: 4 hops. If viewer account is compromised, attacker can reach the database server in 4 lateral moves.

4.4 Incident Pipeline

Trigger Event
User login fails → AuthService catches it
Risk Check
IncidentService calls RiskEngineService to score all servers owned by that user
Threshold Evaluation
Score ≥ 50 → create incident; Score < 50 → monitor only
Incident Created
Incident saved with severity, attack path, source IP, and risk score
Dashboard Updated
Open incident count increases, alert banner appears in UI

🚀 10. How to Run

Prerequisites

  • Java 21 LTS installed
  • Maven 3.9+ installed
  • PostgreSQL 16 running on port 5432
  • Database cybershield_db created
  • Python 3 + requests library for attack scripts

Start the Application

cd cybershield-nexus
mvn spring-boot:run

Open in Browser

http://localhost:8081/login.html
Username: admin   Password: Admin@123

Run Attack Scripts

cd attack-scripts
python run_all_attacks.py   # runs all 3 attacks in sequence
